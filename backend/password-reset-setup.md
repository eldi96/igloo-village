# 관리자 확인형 비밀번호 초기화 설정

현재: 코드 준비, 운영 DB add_owner_managed_password_reset 적용·롤백 검증 완료. 서버 비밀 키 등록 대기, 아직 미배포.

## DB 담당자 확인 내용
- 비공개 테이블 private.password_reset_requests: 대상 회원·아이디·상태·처리자·시간·임시값 해시·실패 횟수·처리 잠금. 실제 비밀번호 원문은 저장하지 않음.
- private.password_reset_limits: 원본 IP 대신 서버에서 만든 해시별 요청 제한.
- password-reset.sql의 새 RPC는 service_role만 실행. 익명/일반 회원은 DB 함수·요청 목록에 직접 접근 불가.
- 계정당 활성 요청 1개, 임시값 30분/1회/5회 실패 제한. 중단된 처리 건은 5분 뒤 본인 확인 후 새 임시값으로 재발급.
- 회원·프로젝트·기존 로그인 권한은 변경하지 않음. 실제 비밀번호 변경은 Vercel 서버의 Supabase Auth Admin API로만 수행.

password-reset.sql은 운영 적용 내역으로 재실행하지 않는다. schema.sql 전체를 운영에 재실행하지 않음.

## 서버 설정
Vercel 프로젝트에 SUPABASE_SECRET_KEY(또는 기존 SUPABASE_SERVICE_ROLE_KEY)를 서버 전용·민감 변수로 등록. 키는 채팅·저장소·브라우저 설정·공개 환경변수에 넣지 않음. SUPABASE_URL은 선택(기존 프로젝트 주소 기본 사용).
관리자 ID는 recovery-config.js에 검증한 기존 eldi 계정만 지정되어 있으며 서버에서 JWT와 현재 승인 상태를 검사한다. 별도 관리자 환경변수로 임의 확대하지 않음.
파이썬 정적 서버에서는 /api/password-reset이 실행되지 않으므로 요청 저장·실제 변경 시험에는 Vercel 서버 환경이 필요하다.

## 운영 절차
로그인 화면의 초기화 요청 → eldi 계정의 초기화 요청 관리 → 강의실 등에서 본인 확인 → 체크 후 발급 → 원문을 당사자에게 직접 전달 → 로그인 화면의 임시 비밀번호로 변경 → 새 비밀번호 설정 후 정상 로그인.
임시값은 로그인 세션을 주지 않고 변경에만 사용한다. 새 비밀번호 설정 전까지 기존 비밀번호는 유지된다. Auth 응답이 불확실하면 이전 임시값을 재활성화하지 않는다. 새 비밀번호 로그인부터 확인한 후 필요 시 5분 뒤 재발급한다.
관리자 자신이 비밀번호를 잊으면 앱 내 본인 승인으로 해결할 수 없으므로 Supabase 소유자 관리 경로를 이용한다.
기존 로그인 세션의 즉시 강제 종료는 이번 범위에 포함하지 않는다.
