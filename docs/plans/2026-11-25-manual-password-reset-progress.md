# 비밀번호 초기화 수동 전환 계획 — 2026-11-25

## 목표와 결정
- 로그인 전: 아이디로 요청만 접수. 아이디 존재 여부는 동일 안내.
- 관리자: eldi만 목록·반려·수동 처리 완료 표시.
- 비밀번호 변경: Supabase SQL Editor에서 관리자가 본인 확인 후 별도 수동 실행.
- 로그인 후: 모든 승인 회원에게 비밀번호 변경 버튼. Supabase Auth updateUser 사용.
- 서버 Secret key가 필요하지 않음. 운영 API는 410으로 중지.
- 기존 테이블/기록/테스트/자동 구현은 보존. 자동 구현은 운영 경로에서 호출하지 않음.

## DB 담당자 검토 사항 (운영 미적용)
1. 기존 테이블 2개는 그대로 둠. 새 테이블/컬럼 없음.
2. request_manual_password_reset: 로그인 전 요청만 허용. 기존 승인/중복/간격 검사 재사용.
3. list_manual_password_reset_requests / resolve_manual_password_reset: 로그인한 eldi만 조회/상태 변경.
4. 이전 자동 발급 함수들의 공개/회원/service_role 실행 권한 제거.
5. manual-password-reset-admin-template.sql은 운영 구조 변경과 별개. 관리자가 직접 실행하는 초안.
   Auth 내부 encrypted_password를 직접 변경하므로 DB 담당자의 검토가 필요함.
   비밀번호 원문을 쿼리에 넣지 않고 무작위로 생성, bcrypt 저장, 결과에서 한 번 확인.
   실제 로그인용 임시 비밀번호는 자동 만료/1회용/변경 강제가 아님. 즉시 직접 변경 안내.
   기존 세션 자동 로그아웃은 이번 범위 아님.
